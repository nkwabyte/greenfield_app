
You are working on an existing, fully functional Next.js application that is already deployed to Vercel and actively in use. The goal is to convert this project into a pnpm-based monorepo that supports both the existing web application and a new Electron desktop application, without breaking the current web deployment or changing user-facing behavior.

The web app must remain deployable via GitHub and Vercel after the conversion.

Primary objectives
	1.	Convert the current single-repo Next.js project into a pnpm workspace monorepo
	2.	Keep the existing web app intact and functional
	3.	Add an Electron desktop application that reuses the same UI and business logic
	4.	Avoid code duplication
	5.	Keep the architecture scalable for future platform additions



Architectural constraints and expectations
	•	Use pnpm workspaces as the package manager
	•	Use Turborepo or an equivalent monorepo task runner compatible with pnpm
	•	The monorepo must contain:
	•	A web app powered by Next.js
	•	A desktop app powered by Electron
	•	Shared packages for business logic and types
	•	The web app must continue to deploy on Vercel by pointing the project root to the web app directory


Required repository structure (conceptual)
The final structure should conceptually resemble:

apps/
  web/        Next.js web application
  desktop/    Electron desktop application

packages/
  shared/     Utilities, helpers, constants
  services/   API clients, auth, storage logic
  types/      Shared TypeScript types

Exact naming is flexible as long as the separation of concerns is respected.

Web application requirements
	•	The web app must remain a standard Next.js project
	•	No UI rewrites are required
	•	No breaking changes to routing, SSR, or API routes
	•	Must continue to build and deploy on Vercel after the monorepo conversion
	•	Vercel should be able to deploy by setting the Root Directory to the web app folder
	•	pnpm must be used for dependency installation and workspace linking



Desktop application requirements
	•	Add a new Electron application inside the monorepo
	•	Electron must load the existing Next.js UI
	•	During development, Electron should load the local Next.js dev server
	•	In production, Electron should load a built version of the web app
	•	Desktop-specific functionality must be isolated to the Electron layer
	•	No web-only assumptions should leak into shared packages



Shared code requirements
	•	Business logic, API calls, auth logic, validation, and shared types should live in shared packages
	•	Shared packages must be platform-agnostic
	•	Web and desktop apps should import from shared packages via workspace aliases
	•	UI components should remain in the web app initially unless abstraction is clearly beneficial



Non-goals and constraints
	•	Do not create separate repositories
	•	Do not duplicate application logic
	•	Do not introduce React Native or mobile targets at this stage
	•	Do not break the current Vercel deployment pipeline
	•	Do not make Electron the primary or root application


Deliverables
	•	A working pnpm monorepo
	•	The web app running and deployable exactly as before
	•	A functional Electron desktop app using the same UI
	•	Clear documentation on:
	•	Running the web app alone
	•	Running the desktop app alone
	•	Running both in development
	•	Building both for production



Focus on outcomes and architectural correctness rather than rigid steps. You have full context of the existing codebase. Make decisions that preserve stability while enabling desktop expansion.
